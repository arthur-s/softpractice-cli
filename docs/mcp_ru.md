# Как пользоваться MCP-сервером SoftPractice

[English](mcp.md) | Русский

Подключи сервер по [инструкции в README](../README_RU.md#mcp-сервер).
Он работает с одним привязанным Git-проектом урока: папку задаёт место запуска
или флаг `--project`. Переключить папку параметром инструмента нельзя.

Настройка `softpractice mcp setup ...` работает из любой папки. На macOS,
Linux и Windows клиент автоматически запускает `softpractice mcp connect`.
Подключение и список инструментов доступны даже без запущенного сервера
урока: запрос к уроку объяснит, как его запустить, сохраняя соединение.
Системная служба или задача автозапуска не устанавливается.

Запусти `softpractice mcp` в папке урока или укажи `--project DIR` и оставь
терминал открытым на время работы. Для смены проекта останови сервер урока
и запусти его в другой папке. Следующий запрос использует новый проект;
перезапускать клиент или повторять настройку не нужно. Одновременно работает
один сервер урока. Он использует локальное TCP-соединение; подключение
клиента использует stdio. Подтверждения действий теряют силу при перезапуске
сервера урока.

## Что можно попросить у агента

Напиши просьбу в чате Codex, Claude или другого MCP-клиента. Агент превращает
её в вызовы инструментов; сам сервер принимает структурированные вызовы,
а не произвольный текст или команды терминала. Запоминать имена инструментов
не обязательно. Упоминай «MCP SoftPractice», если у агента несколько
источников информации.

| Пример просьбы | Инструмент |
| --- | --- |
| «Через MCP SoftPractice покажи статус урока и следующий шаг». | `status` |
| «Покажи текущее задание и его требования». | `task` |
| «Покажи теорию текущего урока». | `material` |
| «Покажи материал урока pa-foundation-01». | `material` с `lesson_id` |
| «Покажи подготовленные подсказки, которые я уже открыл». | `hints` |
| «Запусти публичные проверки урока на моих текущих файлах». | `check` |
| «Отправь закоммиченное решение и подожди результат до 45 секунд». | `submit` с `wait_seconds` |
| «Покажи последний результат проверки». | `result` |
| «Подожди результат проверки до 45 секунд». | `result` с `wait_seconds` |
| «Покажи мои последние отправки этого урока». | `submissions` |
| «Примени доступное обновление урока, сначала показав изменения файлов». | `update` |

Например, начать можно так:

> Через MCP SoftPractice прочитай статус, задание и материал. Объясни
> требования и помоги составить план работы. Решение я хочу написать сам.

Формулировки могут быть другими. `status` возвращает `next_actions`:
инструмент с параметрами, Git-команду или ссылку на страницу. Попроси агента
следовать этим шагам; часть из них требует твоего действия на сайте.

## Инструменты и параметры

Все параметры необязательные. Инструменты без параметров получают `{}`.
Примеры JSON ниже — аргументы инструментов, их не нужно вставлять в терминал.

| Инструмент | Аргументы | Результат и условия |
| --- | --- | --- |
| `status` | `{}` | Аккаунт, привязанный урок и версия, Git HEAD, чистота дерева, последняя отправка и `next_actions`. Читай сначала и после каждого шага. |
| `task` | `{}` | Задание версии урока, на которую рассчитаны файлы в этой папке; также сообщает о доступном переходе или обновлении версии. |
| `material` | `{"lesson_id":"pa-foundation-01"}` или `{}` | Теория указанного урока или урока этой папки по умолчанию. Если теории нет, `material` равен `null`. |
| `hints` | `{}` | Только открытые подсказки. `status` равен `available`, `exhausted` или `unavailable`; `url` ведёт на страницу задания. |
| `check` | `{}` | Запускает опубликованные публичные проверки на рабочем дереве, включая незакоммиченные изменения. Возвращает `passed`, вывод и описание сбоя, если он был. |
| `submit` | `{"wait_seconds":45}` или `{}` | Отправляет закоммиченный HEAD после твоего подтверждения. Нужны чистое дерево и урок, принимающий отправки. Локальные проверки не запускает. Возвращает ID отправки и ссылку на результат; при ожидании — также результат или ошибку ожидания. |
| `result` | `{"submission_id":"<канонический UUID>","wait_seconds":45}` или `{}` | Читает указанную отправку или последнюю по умолчанию. Возвращает `ready`, `pending` или `superseded`. Сразу после перехода последний результат может относиться к предыдущему уроку (`previous_lesson_id`). |
| `submissions` | `{}` | До пяти последних отправок урока, начиная с самой новой. |
| `update` | `{}` | Применяет доступный переход, обновление версии урока или добавляет отсутствующую конфигурацию публичных проверок. Требует чистое дерево, показывает операции с файлами для подтверждения и делает Git-commit обновления. |

`wait_seconds` — целое число **от 0 до 600**. Если не передать его или
передать `0`, инструмент вернётся без ожидания проверки. Значение должно быть
меньше таймаута инструмента в клиенте; сервер предлагает **45 секунд**.
При `pending` вызови `result` снова, соблюдая `next_poll_seconds`, если оно
указано. `ready` означает, что проверка завершилась: посмотри в результате,
принято ли решение, нужна ли доработка или произошёл технический сбой.
`superseded` означает, что у этой проверки результата не будет; нужна отправка
нового commit.

`check` сохраняет последние 32 KiB общего stdout/stderr. Если начало вывода
обрезано, `truncated` равен `true`. Неудачная проверка возвращает
`passed: false`; невозможность вызвать инструмент, например отсутствие
авторизации, — ошибку инструмента.

Задание и теория также доступны как Markdown-ресурсы:

- `softpractice://lesson/task`
- `softpractice://lesson/material`

Доступ к ресурсам зависит от клиента. Инструменты `task` и `material`
предоставляют тот же контент без отдельного просмотра ресурсов.

## Работа с уроком

1. Прочитай `status`, затем `task` и `material`. При необходимости посмотри
   открытые `hints`.
2. Работай над решением. Редактирование файлов и Git-commit — отдельные
   действия в редакторе или терминале; таких инструментов у MCP-сервера нет.
3. Вызови `check`: он проверит и незакоммиченные изменения. Когда решение
   готово, закоммить все изменения.
4. Вызови `submit` и проверь урок и commit в окне подтверждения. Подтверди
   действие в интерфейсе клиента: ответ «да» в чате не заменяет это окно.
5. Прочитай `result` или подожди его с `wait_seconds`. Если ожидание после
   отправки завершилось ошибкой, решение уже могло уйти: вызови `result`
   с полученным ID, прежде чем повторять отправку.
6. Прочитай обратную связь. Если `questions_answerable` равен `true`, сам
   ответь на вопросы рецензента на странице `result_url`. После принятия
   прочитай `status` и вызови `update`, когда он предложен. Перед
   подтверждением просмотри список файлов.

## Что остаётся вне MCP

Сервер не предоставляет `login`, `logout`, `starter`, `project restore`,
`set` и `open`. В ответ на такую просьбу агент может предложить команду
терминала или использовать свои отдельные инструменты терминала и браузера;
это не вызовы MCP SoftPractice.

Следующую подсказку открывай сам на странице задания. MCP-сервер не открывает
подсказки, не возвращает рекомендации рецензента (`--directions`) и текст
его вопросов. Он отдаёт замечания и число вопросов; прочитай вопросы
и ответь на них на странице результата. Инструкции сервера также запрещают
агенту получать эти тексты через CLI и отвечать за тебя. Эти границы задают
правила работы агента, но не отключают его отдельные инструменты терминала.

## Если что-то не работает

| Симптом или код | Что сделать |
| --- | --- |
| `lesson_server_not_running` | Запусти `softpractice mcp` в папке урока или с `--project DIR`, затем повтори запрос. Перезапускать клиент не нужно. |
| `lesson_server_unavailable` | Выполни `softpractice mcp status` в терминале для диагностики локального подключения. |
| Сервер не запускается | Проверь, что клиент видит установленный CLI; при необходимости укажи полный путь к исполняемому файлу. Проверь, что `--project` указывает на существующую папку. |
| `not_git_repository` или `project_not_linked` | Укажи Git-проект урока, а не родительскую папку. При необходимости скачай или восстанови проект через CLI. |
| `login_required` | Выполни `softpractice login` в терминале на том же компьютере и повтори вызов инструмента. |
| `checks_not_published` | Сверь `.softpractice/checks.json` с опубликованными проверками урока. Примени предложенное обновление или просмотри команды и запусти `softpractice check` в терминале. |
| `confirmation_unavailable` | Клиент не умеет запрашивать подтверждение через MCP elicitation. Сам выполни `softpractice submit` или `softpractice update` в терминале. |
| `declined` | Ты отклонил или закрыл подтверждение; ничего не отправлено и не применено. Повтори вызов, когда будешь готов. |
| `changed_since_confirmation` | Проект или урок изменился во время подтверждения. Прочитай `status` и вызови инструмент снова, чтобы увидеть новое подтверждение. |
| Таймаут инструмента | Уменьши `wait_seconds` или увеличь таймаут в клиенте. Перед повторным `submit` проверь `status` или `result`. |

Ошибки инструментов содержат `isError` и JSON с `code`, `message`
и, когда нужно, `action`. У ошибок API могут быть также `http_status`,
`api_code` и `support_id`. Сохрани support ID, если сообщаешь о проблеме.
