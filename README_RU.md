# SoftPractice CLI

[English](https://github.com/arthur-s/softpractice-cli/blob/main/README.md) | Русский

CLI-клиент [SoftPractice](https://softpractice.ru) — онлайн-тренажёра для
проектной практики программирования с AI-наставником.

SoftPractice позволяет работать над реалистичными задачами в локальных
Git-проектах, отправлять зафиксированные решения на проверку, получать обратную
связь и последовательно проходить уроки практикума. CLI связывает локальный
процесс разработки с workspace в SoftPractice.

## Установка

```bash
npm install -g @softpractice/softpractice-cli
```

Проверь установку:

```bash
softpractice --help
```

## Начало работы

Войди в SoftPractice:

```bash
softpractice login
```

Скачай starter-проект текущего практикума:

```bash
softpractice starter
```

Перейди в созданный каталог, проверь состояние проекта и прочитай задание:

```bash
cd <каталог-проекта>
softpractice status
softpractice task
softpractice material
```

Работай над проектом и фиксируй изменения в Git. Когда решение будет готово,
отправь текущий коммит и дождись результата:

```bash
softpractice submit --wait
```

Результат можно посмотреть снова в любой момент или открыть в браузере:

```bash
softpractice result
softpractice open result
```

После принятия решения примени переход к следующему доступному уроку:

```bash
softpractice update
```

`softpractice status` всегда заканчивается следующим шагом.

## Основные команды

| Команда | Описание |
| --- | --- |
| `softpractice login` | Войти через браузер |
| `softpractice starter` | Скачать проект первого урока |
| `softpractice status` | Показать состояние проекта и следующий шаг |
| `softpractice task` | Показать задание |
| `softpractice material` | Показать теоретический материал; `--lesson ID` — другого урока |
| `softpractice hint` | Показать открытые подсказки; следующая открывается на странице задания |
| `softpractice check` | Запустить публичные проверки текущего рабочего дерева |
| `softpractice submit` | Отправить текущую зафиксированную Git-ревизию; `--wait` дожидается результата |
| `softpractice result` | Показать результат проверки; `--wait` дожидается его, `--directions` добавляет рекомендации рецензента |
| `softpractice submissions` | Показать последние отправки урока |
| `softpractice update` | Применить переход к следующему уроку или перейти на новую версию текущего урока (заменяет только файлы урока, ваши файлы не трогает; до конца урока необязательно) |
| `softpractice open` | Открыть задание, материал или последний результат в браузере |
| `softpractice mcp` | Запустить опциональный локальный MCP-сервер урока для MCP-клиентов |
| `softpractice mcp status` | Проверить работающий MCP-сервер урока и его проект |
| `softpractice mcp setup` | Встроенная настройка MCP для `claude-desktop` или `codex-desktop` |
| `softpractice mcp remove` | Убрать запись MCP из настроек `claude-desktop` или `codex-desktop` |
| `softpractice project restore` | Восстановить проект из последней подходящей ревизии |

Подробную справку можно получить командой `softpractice help <команда>`.

## Локальные проверки

Во время работы запускай публичные проверки вместе с незакоммиченными
изменениями:

```bash
softpractice check
```

Команда использует текущее рабочее дерево и ничего не отправляет на сервер.
Если проект использует виртуальное окружение Python, сначала активируй его,
чтобы команда `python3` из конфигурации разрешилась в нужный интерпретатор.

Чтобы перед каждой отправкой автоматически проверять точную зафиксированную
ревизию, включи автопроверки:

```bash
softpractice set auto-checks true
```

`softpractice submit --checks` включает такую проверку для одной отправки. В
отличие от `softpractice check`, проверка перед отправкой требует чистое рабочее
дерево и запускается в изолированном снимке `HEAD`.


Некоторым урокам для проверок нужны данные предыдущих принятых решений.
CLI скачивает и проверяет их из вашего workspace перед запуском; для таких
проверок требуется подключение к сети. Временные данные не попадают в проект
или отправляемое решение. Если workspace сменил урок во время проверки,
обновите проект и повторите запуск.

## Вопросы рецензента

Если у рецензента есть вопросы к решению, `softpractice result` и
`softpractice status` сообщают об этом и дают ссылку на страницу результата:
отвечать нужно там.

## Машиночитаемый вывод

`status`, `task`, `material`, `hint`, `result`, `submissions` и `submit`
принимают `--json`. У каждого документа есть поле `kind`; при ошибке команда
выводит документ `softpractice.error`, в том числе при неверных аргументах
(код `usage`) и при отказе в подтверждении `submit` (код `declined`).

```bash
softpractice result --wait --timeout 10m --json
```

Коды выхода: `0` — готово, `1` — ошибка, `2` — неверные аргументы, `3` —
проверка ещё не готова, `4` — проверка заменена, результата не будет.

## Работа с ИИ-агентом

Основной способ работы с SoftPractice в любом coding-агенте с доступом к
терминалу (Claude Code, Codex, Cursor, OpenCode, Antigravity, DeepSeek harness
и др.) — напрямую через CLI и корневые файлы `AGENTS.md` / `CLAUDE.md`
стартового проекта. Отдельная настройка MCP для этого не нужна.

- **Прямая работа через CLI:** агент ведёт урок обычными командами (`status`,
  `task`, `material`, `hint`, `check`, `submit`, `result`, `update`), используя
  `--json` у команд, которые его поддерживают (см.
  [Машиночитаемый вывод](#машиночитаемый-вывод)).
- **Встроенные правила проекта:** в корне каждого стартового проекта уже лежат
  `AGENTS.md` и `CLAUDE.md` (`CLAUDE.md` подключает `@AGENTS.md`), поэтому
  coding-агенты автоматически получают рабочий процесс и учебные границы.
  Оба файла хранятся в Git, `softpractice update` их не заменяет, и в
  отправляемое решение они не входят.
- **Что остаётся за тобой:** открывать новые подсказки на странице задания,
  отвечать на вопросы рецензента на странице результата и решать, когда делать
  commit, отправку или обновление урока.

### Быстрый старт: промпт для агента

Скопируй этот промпт в своего coding-агента, чтобы установить CLI, войти в
аккаунт, скачать стартовый проект и изучить первое задание до написания кода:

```text
Настрой SoftPractice CLI и подготовь проект урока:
1. Установи CLI командой `npm install -g @softpractice/softpractice-cli`. Если npm недоступен, установи через Go с версией последнего релиза (`go install -ldflags "-X main.cliVersion=<версия-релиза>" github.com/arthur-s/softpractice-cli/cmd/softpractice@latest`), чтобы `softpractice version` показывала семантическую версию (а не `dev`). Проверь установку командами `softpractice --help` и `softpractice version`.
2. Запусти `softpractice login`, покажи мне ссылку и код подтверждения и дождись, пока я подтвержу вход в браузере.
3. Выполни `softpractice starter`, чтобы скачать стартовый проект. Если практикум ещё не начат, подскажи мне открыть https://softpractice.ru/learning, выбрать и начать практикум, а затем повтори `softpractice starter`.
4. Перейди в созданную папку проекта, прочитай корневой `AGENTS.md` и выполни `softpractice status` и `softpractice task`.
5. Кратко перескажи требования задания и остановись: не пиши решение, не делай Git commit и не запускай `softpractice submit`, пока мы не обсудим план.
```

## MCP-сервер

MCP — это **опциональная** интеграция. Если у coding-агента уже есть доступ к
терминалу, проще работать напрямую через CLI и `AGENTS.md` (см.
[Работа с ИИ-агентом](#работа-с-ии-агентом)) — без дополнительной настройки.

Используй `softpractice mcp` в первую очередь, если:

- у клиента **нет доступа к терминалу** (например, Claude Desktop); или
- нужны **встроенные окна подтверждения MCP** (MCP elicitation) для `submit` и
  `update`.

### 1. Подключи клиент

Сначала установи CLI (см. [Установка](#установка)). Проект урока на этом этапе
не нужен. Выбери подходящий способ:

**Вариант A — через промпт агенту (проще всего для любого coding-агента):**

```text
Зарегистрируй в своих настройках MCP stdio-сервер `softpractice`:
- command: `softpractice` (или полный путь из `which softpractice` / `where softpractice`, если клиент не наследует PATH терминала)
- args: `["mcp", "connect"]`
Остальные настройки не трогай и сам сервер урока не запускай. Сообщи, если нужно перезапустить клиент, и напомни мне запустить `softpractice mcp` в папке проекта урока (или `softpractice mcp --project <путь>`).
```

**Вариант B — встроенный шорткат для Desktop-приложений (Claude Desktop / Codex Desktop):**

Перед настройкой Claude Desktop открой приложение хотя бы один раз. После
настройки полностью закрой Desktop-приложение и запусти его снова:

```bash
softpractice mcp setup claude-desktop
# или
softpractice mcp setup codex-desktop
```

Убрать запись позже (не останавливая запущенный сервер урока):

```bash
softpractice mcp remove claude-desktop
# или
softpractice mcp remove codex-desktop
```

Обе команды записывают путь к нативному исполняемому файлу CLI и
`["mcp", "connect"]`, сохраняют остальные настройки и оставляют резервную копию
`.bak` (подробнее про `--print` и пути файлов — в `softpractice help mcp` и
[гайде по использованию MCP](docs/mcp_ru.md)).

**Вариант C — вручную (универсальный stdio-контракт):**

Любой MCP-совместимый клиент подключается по одному и тому же stdio-контракту
(`command`: `softpractice` или полный путь к программе, `args`:
`["mcp", "connect"]`; если клиент позволяет задать таймаут инструментов,
рекомендуется не меньше `180` секунд):

```json
{
  "mcpServers": {
    "softpractice": {
      "command": "softpractice",
      "args": ["mcp", "connect"]
    }
  }
}
```

### 2. Запусти сервер урока

Войди в аккаунт и запусти локальный сервер урока для Git-проекта, скачанного
через `softpractice starter` или восстановленного через
`softpractice project restore`:

```bash
softpractice login
cd /path/to/your/lesson-project
softpractice mcp
```

Либо укажи путь к проекту из любой папки:

```bash
softpractice mcp --project /path/to/your/lesson-project
```

Оставь терминал открытым. Зачем нужен отдельный локальный сервер урока:

- **Выбор и проверка проекта:** только запуск `softpractice mcp` задаёт
  активный Git-репозиторий и проверяет привязку проекта к SoftPractice.
  Инструменты MCP не могут переключать папку, а сервер использует сохранённый
  вход CLI и сам не запускает авторизацию через браузер.
- **Независимый жизненный цикл:** на macOS, Linux и Windows клиент сам
  запускает и держит процесс `softpractice mcp connect` по stdio (системная
  служба или автозапуск не устанавливаются). Сервер `softpractice mcp` можно
  запускать, останавливать и перезапускать без перезапуска MCP-клиента, затем
  повторить запрос (при перезапуске незавершённые подтверждения теряют силу).
- **Только локальное подключение:** сервер урока слушает `127.0.0.1:39473`
  (это не HTTP URL) и требует случайный ключ текущего запуска, сохраняемый в
  пользовательской папке настроек CLI. Оба процесса должны работать на одном
  компьютере под одним пользователем и с одинаковым `SOFTPRACTICE_CONFIG_DIR`,
  если эта переменная задана.

Одновременно работает один сервер урока. Чтобы переключиться на другой проект,
останови его через Ctrl+C и запусти в другой папке — повторная настройка и
перезапуск клиента не нужны. `softpractice mcp` всегда запускает локальный
сервер, в том числе при перенаправленном stdin и фоновом запуске; команда
настройки не принимает `--project`.

Проверить работающий сервер урока из любой папки (проект и вход не нужны):

```bash
softpractice mcp status
softpractice mcp status --json
```

Команда проверяет живое соединение (оставшийся после сбоя файл ключа не
считается признаком работы; остановленный сервер возвращает `not_running`) и
показывает статус сервера урока, а не процесса `mcp connect`. Остановить сервер
можно через Ctrl+C в его терминале.

### 3. Использование сервера

Сервер предоставляет девять инструментов. Ты пишешь агенту обычным языком,
а он выбирает инструмент и передаёт параметры. Это имена инструментов MCP,
не slash-команды. В [гайде по использованию MCP](docs/mcp_ru.md) есть примеры
просьб, точные параметры, порядок работы с уроком и разбор ошибок.

| Инструмент | Что делает |
| --- | --- |
| `status` | Состояние проекта и `next_actions`: какой инструмент вызвать дальше или какая страница нужна тебе |
| `task` | Задание урока в этой папке |
| `material` | Теоретический материал; `lesson_id` — для другого урока |
| `hints` | Подсказки, которые ты уже открыл |
| `check` | Запустить публичные проверки для рабочего дерева |
| `submit` | Отправить закоммиченный `HEAD` после твоего подтверждения; `wait_seconds` — дождаться результата |
| `result` | Результат проверки; `wait_seconds` — дождаться его |
| `submissions` | Последние отправки урока |
| `update` | Применить обновление урока после того, как ты подтвердишь список файлов |

Задание и материал доступны также как resources
`softpractice://lesson/task` и `softpractice://lesson/material`.

Что сервер оставляет тебе:

- `submit` и `update` просят подтверждения в клиенте и показывают commit или
  список файлов. Если клиент не умеет спрашивать (не поддерживает MCP
  elicitation), они ничего не делают и возвращают `confirmation_unavailable`;
  тогда выполни `softpractice submit` или `softpractice update` в терминале.
- В результатах никогда нет рекомендаций рецензента (`--directions`) и текста
  его вопросов. На вопросы ты отвечаешь на странице результата; агент получает
  только их число и ссылку.
- Агент видит только подсказки, которые ты уже открыл; следующую ты открываешь
  на странице задания.
- `check` запускает только проверки, которые сервер публикует для урока. Если
  `.softpractice/checks.json` отличается, он возвращает
  `checks_not_published`: посмотри команды и запусти `softpractice check` в
  терминале.
- `login`, `logout`, `starter`, `project restore`, `set` и `open` через MCP
  недоступны.

Эти ограничения относятся к инструментам MCP. Агент, который может выполнять
команды в терминале, может вызвать и сами команды `softpractice`.

Ошибки приходят как результаты инструментов с `isError` и JSON
`{"error": {"code", "message", "action"}}`; в `action` написано, что сделать
тебе, например при `login_required` — выполнить `softpractice login`.

Имена и описания инструментов — на английском, их читает модель. Сообщения для
тебя — подтверждение и ошибки — на языке CLI (см. ниже); если язык нигде не
задан, MCP-сервер говорит по-русски, на языке курса. Чтобы сменить язык, задай
`SOFTPRACTICE_LANGUAGE` в `env` сервера в настройках клиента или передай
`--lang en` перед `mcp`.

## Язык

SoftPractice CLI поддерживает английский и русский языки и по возможности
выбирает язык по системной локали.

Язык можно сохранить явно:

```bash
softpractice set lang en
softpractice set lang ru
```

Для одной команды язык можно переопределить флагом:

```bash
softpractice --lang en status
```

## Восстановление проекта

Если исходный каталог проекта недоступен, восстанови последнюю подходящую
ревизию в новый каталог:

```bash
softpractice project restore \
  --practicum <id-практикума> \
  --directory ./restored-project
```

CLI никогда не перезаписывает существующий каталог проекта.
