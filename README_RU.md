# SoftPractice CLI

[English](https://github.com/arthur-s/softpractice-cli/blob/main/README.md) | Русский

CLI-клиент [SoftPractice](https://softpractice.ru) — онлайн-тренажёра для
проектной практики программирования с AI-наставником.

SoftPractice позволяет работать над реалистичными задачами в локальных
Git-проектах, отправлять зафиксированные решения на проверку, получать обратную
связь и последовательно проходить уроки практикума. CLI связывает локальный
процесс разработки с workspace в SoftPractice.

## Установка

```bash
npm install -g @softpractice/softpractice-cli
```

Проверь установку:

```bash
softpractice --help
```

## Начало работы

Войди в SoftPractice:

```bash
softpractice login
```

Скачай starter-проект текущего практикума:

```bash
softpractice starter
```

Перейди в созданный каталог, проверь состояние проекта и прочитай задание:

```bash
cd <каталог-проекта>
softpractice status
softpractice task
softpractice material
```

Работай над проектом и фиксируй изменения в Git. Когда решение будет готово,
отправь текущий коммит и дождись результата:

```bash
softpractice submit --wait
```

Результат можно посмотреть снова в любой момент или открыть в браузере:

```bash
softpractice result
softpractice open result
```

После принятия решения примени переход к следующему доступному уроку:

```bash
softpractice update
```

`softpractice status` всегда заканчивается следующим шагом.

## Основные команды

| Команда | Описание |
| --- | --- |
| `softpractice login` | Войти через браузер |
| `softpractice starter` | Скачать проект первого урока |
| `softpractice status` | Показать состояние проекта и следующий шаг |
| `softpractice task` | Показать задание |
| `softpractice material` | Показать теоретический материал; `--lesson ID` — другого урока |
| `softpractice hint` | Показать открытые подсказки; следующая открывается на странице задания |
| `softpractice check` | Запустить публичные проверки текущего рабочего дерева |
| `softpractice submit` | Отправить текущую зафиксированную Git-ревизию; `--wait` дожидается результата |
| `softpractice result` | Показать результат проверки; `--wait` дожидается его, `--directions` добавляет рекомендации рецензента |
| `softpractice submissions` | Показать последние отправки урока |
| `softpractice update` | Применить переход к следующему уроку или перейти на новую версию текущего урока (заменяет только файлы урока, ваши файлы не трогает; до конца урока необязательно) |
| `softpractice open` | Открыть задание, материал или последний результат в браузере |
| `softpractice mcp` | Запустить MCP-сервер для Claude Code, Codex, Claude Desktop и других агентов |
| `softpractice mcp setup codex-desktop` | Подключить MCP к Codex Desktop без установки Codex CLI |
| `softpractice mcp status` | Проверить работающий сервер и его проект |
| `softpractice mcp remove codex-desktop` | Убрать подключение из настроек Codex |
| `softpractice project restore` | Восстановить проект из последней подходящей ревизии |

Подробную справку можно получить командой `softpractice help <команда>`.

## Локальные проверки

Во время работы запускай публичные проверки вместе с незакоммиченными
изменениями:

```bash
softpractice check
```

Команда использует текущее рабочее дерево и ничего не отправляет на сервер.
Если проект использует виртуальное окружение Python, сначала активируй его,
чтобы команда `python3` из конфигурации разрешилась в нужный интерпретатор.

Чтобы перед каждой отправкой автоматически проверять точную зафиксированную
ревизию, включи автопроверки:

```bash
softpractice set auto-checks true
```

`softpractice submit --checks` включает такую проверку для одной отправки. В
отличие от `softpractice check`, проверка перед отправкой требует чистое рабочее
дерево и запускается в изолированном снимке `HEAD`.

## Вопросы рецензента

Если у рецензента есть вопросы к решению, `softpractice result` и
`softpractice status` сообщают об этом и дают ссылку на страницу результата:
отвечать нужно там.

## Машиночитаемый вывод

`status`, `task`, `material`, `hint`, `result`, `submissions` и `submit`
принимают `--json`. У каждого документа есть поле `kind`; при ошибке команда
выводит документ `softpractice.error`, в том числе при неверных аргументах
(код `usage`) и при отказе в подтверждении `submit` (код `declined`).

```bash
softpractice result --wait --timeout 10m --json
```

Коды выхода: `0` — готово, `1` — ошибка, `2` — неверные аргументы, `3` —
проверка ещё не готова, `4` — проверка заменена, результата не будет.

## Инструкции для агентов

В корне каждого стартового проекта уже есть `AGENTS.md` и `CLAUDE.md`, поэтому
Codex, Claude Code и другие агенты сразу получают правила проекта. Файлы
хранятся в Git, `softpractice update` их не заменяет, и в отправляемое решение
они не входят.

## MCP-сервер

`softpractice mcp` соединяет агента с уроком SoftPractice: агент может читать
задание и теорию, запускать публичные проверки, отправлять commit и читать
результат.

### Настрой один раз из любой папки

Установи CLI (см. [Установка](#установка)) и настрой Desktop-клиент.
Перед настройкой Claude Desktop установи и открой приложение хотя бы один раз.
Проект урока на этом этапе не нужен:

```bash
softpractice mcp setup claude-desktop
# или
softpractice mcp setup codex-desktop
```

После настройки полностью закрой Desktop-клиент и запусти его снова,
чтобы он прочитал настройки подключения.

Команда записывает абсолютный путь к CLI и аргументы `mcp connect`.
Она только меняет настройки: сервер не запускается, служба с автозапуском
при включении компьютера не создаётся.
Остальные настройки сохраняются, прежний файл остаётся рядом как `.bak`.
Claude Desktop использует `claude_desktop_config.json`; на Windows команда
также находит конфигурацию версии из Microsoft Store. Codex использует
`~/.codex/config.toml` (или `$CODEX_HOME/config.toml`) и таймаут инструментов
180 секунд. Эти настройки общие для Codex Desktop, CLI и расширения IDE.
Для настройки Desktop-приложения устанавливать Codex CLI не нужно.

Для ручной настройки добавь `--print`: команда выведет JSON или TOML,
не меняя файл настроек. Если запись `softpractice` уже есть, замени её,
чтобы не создавать дубликат.

### Запусти сервер урока

Войди в аккаунт и запусти сервер в Git-проекте, скачанном через
`softpractice starter` или восстановленном через `softpractice project restore`:

```bash
softpractice login
cd /path/to/your/lesson-project
softpractice mcp
```

Либо укажи проект при запуске из любой папки:

```bash
softpractice mcp --project /path/to/your/lesson-project
```

Оставь терминал открытым. Перед подключением клиентов сервер проверяет
Git-репозиторий и привязку проекта к SoftPractice. Он использует сохранённый
вход CLI и сам не запускает авторизацию.

На macOS, Linux и Windows клиент автоматически запускает
`softpractice mcp connect` и общается с ним через stdio. Этот процесс
подключения работает отдельно от сервера урока, запущенного в терминале.
Он сохраняет MCP-подключение, даже когда сервер урока не запущен.
Можно открыть Claude Desktop или Codex Desktop до запуска урока: инструменты
остаются доступны в списке, а запрос к уроку объяснит, как запустить сервер.
Запускай, останавливай и перезапускай сервер урока без перезапуска Desktop,
затем повтори запрос. Подтверждения действий теряют силу при перезапуске
сервера урока. Системная служба не устанавливается: процесс подключения
запускает сам клиент.

Сервер урока слушает `127.0.0.1:39473`. Подключение требует случайный ключ,
создаваемый заново при каждом запуске и сохранённый в пользовательской папке
настроек CLI. Оба процесса должны работать на одном компьютере под одним
пользователем и с одинаковым `SOFTPRACTICE_CONFIG_DIR`, если эта переменная
задана. Этот адрес не является HTTP URL.

Одновременно на компьютере работает один сервер урока. Для смены проекта
останови его через Ctrl+C и запусти в другой папке. Следующий запрос
использует новый проект.
Повторять `setup` не нужно.

### Claude Code и Codex CLI

Для подключения к тому же серверу, который ты запускаешь вручную:

```bash
claude mcp add --transport stdio --scope user softpractice -- softpractice mcp connect
# или, если настройки ещё не записаны через setup codex-desktop:
codex mcp add softpractice -- softpractice mcp connect
```

Если клиент не находит `softpractice`, укажи полный путь к программе.
Подробнее — в [документации Claude Code](https://code.claude.com/docs/en/mcp)
и [документации Codex](https://developers.openai.com/codex/mcp).

`softpractice mcp` всегда запускает локальный сервер, в том числе при
перенаправленном stdin и фоновом запуске. Проект выбирается только при запуске
сервера. `setup` записывает команду подключения и не принимает `--project`.
Для работы инструментов с уроком сервер урока должен быть запущен.

### Проверка сервера

Из любой папки проверь, какой сервер сейчас работает:

```bash
softpractice mcp status
softpractice mcp status --json
```

Команда проверяет соединение с сервером и показывает папку урока, PID,
локальный адрес и версию CLI. Остановленный сервер возвращает состояние
`not_running`; оставшийся после сбоя файл ключа не считается признаком работы.
Для этой проверки не нужны проект урока и вход в аккаунт. Это статус
сервера урока, а не процесса подключения клиента. Информация об уроке доступна
через `softpractice status` и, при работающем сервере урока, инструмент MCP
`status`.

### Остановка и удаление подключения

Чтобы остановить сервер урока, нажми Ctrl+C в терминале, где он запущен.
MCP-подключение остаётся активным, но запросы к уроку предложат запустить
сервер урока. Запусти его снова и повтори запрос; перезапускать клиент не нужно.

Чтобы убрать подключение из настроек клиента, выполни из любой папки:

```bash
softpractice mcp remove claude-desktop
# или
softpractice mcp remove codex-desktop
```

Команда удаляет только запись SoftPractice, сохраняет остальные настройки
и создаёт резервную копию `.bak`. Повторный запуск безопасен: если записи
или файла уже нет, ничего не меняется. Перезапусти клиент, чтобы применить
изменение. У Codex это общие настройки Desktop, CLI и расширения IDE;
настройки отдельных проектов могут переопределять их.

Удаление подключения не останавливает сервер урока. Чтобы вернуть подключение,
снова выполни соответствующую команду `softpractice mcp setup`.

### Использование сервера

Сервер предоставляет девять инструментов. Ты пишешь агенту обычным языком,
а он выбирает инструмент и передаёт параметры. Это имена инструментов MCP,
не slash-команды. В [гайде по использованию MCP](docs/mcp_ru.md) есть примеры
просьб, точные параметры, порядок работы с уроком и разбор ошибок.

| Инструмент | Что делает |
| --- | --- |
| `status` | Состояние проекта и `next_actions`: какой инструмент вызвать дальше или какая страница нужна тебе |
| `task` | Задание урока в этой папке |
| `material` | Теоретический материал; `lesson_id` — для другого урока |
| `hints` | Подсказки, которые ты уже открыл |
| `check` | Запустить публичные проверки для рабочего дерева |
| `submit` | Отправить закоммиченный `HEAD` после твоего подтверждения; `wait_seconds` — дождаться результата |
| `result` | Результат проверки; `wait_seconds` — дождаться его |
| `submissions` | Последние отправки урока |
| `update` | Применить обновление урока после того, как ты подтвердишь список файлов |

Задание и материал доступны также как resources
`softpractice://lesson/task` и `softpractice://lesson/material`.

Что сервер оставляет тебе:

- `submit` и `update` просят подтверждения в клиенте и показывают commit или
  список файлов. Если клиент не умеет спрашивать (не поддерживает MCP
  elicitation), они ничего не делают и возвращают `confirmation_unavailable`;
  тогда выполни `softpractice submit` или `softpractice update` в терминале.
- В результатах никогда нет рекомендаций рецензента (`--directions`) и текста
  его вопросов. На вопросы ты отвечаешь на странице результата; агент получает
  только их число и ссылку.
- Агент видит только подсказки, которые ты уже открыл; следующую ты открываешь
  на странице задания.
- `check` запускает только проверки, которые сервер публикует для урока. Если
  `.softpractice/checks.json` отличается, он возвращает
  `checks_not_published`: посмотри команды и запусти `softpractice check` в
  терминале.
- `login`, `logout`, `starter`, `project restore`, `set` и `open` через MCP
  недоступны.

Эти ограничения относятся к инструментам MCP. Агент, который может выполнять
команды в терминале, может вызвать и сами команды `softpractice`.

Ошибки приходят как результаты инструментов с `isError` и JSON
`{"error": {"code", "message", "action"}}`; в `action` написано, что сделать
тебе, например при `login_required` — выполнить `softpractice login`.

Имена и описания инструментов — на английском, их читает модель. Сообщения для
тебя — подтверждение и ошибки — на языке CLI (см. ниже); если язык нигде не
задан, MCP-сервер говорит по-русски, на языке курса. Чтобы сменить язык, задай
`SOFTPRACTICE_LANGUAGE` в `env` сервера в настройках клиента или передай
`--lang en` перед `mcp`.

## Язык

SoftPractice CLI поддерживает английский и русский языки и по возможности
выбирает язык по системной локали.

Язык можно сохранить явно:

```bash
softpractice set lang en
softpractice set lang ru
```

Для одной команды язык можно переопределить флагом:

```bash
softpractice --lang en status
```

## Восстановление проекта

Если исходный каталог проекта недоступен, восстанови последнюю подходящую
ревизию в новый каталог:

```bash
softpractice project restore \
  --practicum <id-практикума> \
  --directory ./restored-project
```

CLI никогда не перезаписывает существующий каталог проекта.
